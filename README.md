# Symbol-Web · ASCII Studio

## Description / Описание

Веб-студия на Go: превращает текст в ASCII-арт с баннерами `standard`, `shadow` и `thinkertoy`. Поддерживает несколько строк, подсказки продолжения текста, выбор баннера по правилам и творческие варианты с помощью LLM. Без настроенного LLM приложение полностью работает в детерминированном **mock-режиме**, без ключа и сети.

Интерфейс вдохновлён [Astana Hub](https://astanahub.com/): гарнитура Golos Text, зелёный `#2c9d62`, фиолетовый `#b554ff` и тема технологического сообщества Казахстана. Лаймовые акценты и композиция студии разработаны для этого приложения. Это самостоятельный проект, не официальный сервис фонда.

- Go 1.22+, только стандартная библиотека; внешних Go-зависимостей нет.
- HTML-шаблоны `html/template`, адаптивный CSS и обычный JavaScript без сборки и CDN.
- Настоящая HTML-форма работает без JavaScript; с JavaScript результат обновляется через `fetch`.
- Подсказки через 300 мс после ввода, рекомендация с объяснением, панель творческих вариантов.
- Копирование, скачивание `.txt` и локальная история в браузере.
- Проверка входных данных, ограничение размера запросов, общий таймаут LLM 10 секунд.
- Повтор временно неудавшегося LLM-запроса и ограниченный кэш подсказок на 5 минут.

## Usage / Как запустить

Нужен Go **1.22 или новее**. Node.js, npm, база данных и API-ключ для запуска не нужны.

```sh
git clone https://github.com/ernat-soltanbekov/symbol-web.git
cd symbol-web
go test ./...
go run cmd/server/main.go
```

Откройте **http://localhost:8080**. Запускайте из корня репозитория: сервер читает оттуда `templates/`, `static/` и файлы баннеров. `Ctrl+C` завершает активные запросы и останавливает сервер.

Переменные перечислены в [.env.example](.env.example). Сервер читает окружение при запуске; файл `.env` **автоматически не загружается**. При необходимости:

```sh
cp .env.example .env
# Измените .env, затем загрузите его в текущую оболочку:
set -a
. ./.env
set +a
go run cmd/server/main.go
```

| Переменная | Значение |
| --- | --- |
| `LLM_BASE_URL` | Пусто: mock. Адрес Ollama или OpenAI-совместимого сервера: live. |
| `LLM_MODEL` | Имя установленной/доступной модели; обязательно в live-режиме. В коде модели по умолчанию нет. |
| `LLM_API_KEY` | Необязательный Bearer-ключ для сервера, который требует авторизацию. |
| `ADDR` | Адрес прослушивания, по умолчанию `:8080`. Например, `127.0.0.1:8081`. |

Для локального Ollama установите и запустите Ollama, загрузите выбранную модель и укажите **её фактическое имя**:

```sh
export LLM_BASE_URL='http://localhost:11434'
export LLM_MODEL='имя-вашей-установленной-модели'
go run cmd/server/main.go
```

Для OpenAI-совместимого сервера:

```sh
export LLM_BASE_URL='https://your-provider.example/v1'
export LLM_MODEL='имя-доступной-модели'
export LLM_API_KEY='ваш-ключ'
go run cmd/server/main.go
```

В PowerShell используйте `$env:LLM_BASE_URL = 'http://localhost:11434'` и `$env:LLM_MODEL = 'имя-модели'`. Для возврата в mock-режим удалите `LLM_BASE_URL` из окружения. Не добавляйте `.env` или реальные ключи в Git; `.gitignore` исключает их.

Сборка отдельного бинарного файла:

```sh
go build -o bin/symbol-web ./cmd/server
./bin/symbol-web
```

## Implementation Details / Детали реализации

### Генератор

Каждый файл баннера содержит 95 печатных ASCII-символов, по восемь строк на символ и одну строку-разделитель. Генератор проверяет структуру файла и соединяет соответствующие строки букв слева направо. Допустимы символы ASCII 32–126 и переводы строк; кириллица, emoji, табуляция и управляющие символы возвращают `400`. Лимит — 1000 символов исходного ввода.

Поддерживаются настоящие переводы строк, Windows CRLF и буквальная последовательность `\n`. Пустые строки сохраняются. Небольшие файлы шрифтов читаются по разрешённому имени при каждом запросе: удаление или повреждение файла обнаруживается даже после успешной генерации. Общего изменяемого состояния генератора нет. Неизвестное имя — `400`, отсутствующий файл — `404`, повреждённый шрифт — `500`.

### HTTP API

Все JSON-ошибки имеют форму `{"error":"Понятное сообщение"}`. API принимает один JSON-объект с полем `text`, отклоняет неизвестные поля, неподходящие символы и запросы более 64 KiB. Результат HTML экранируется средствами `html/template`; динамический текст отображается через `textContent`.

| Метод и путь | Вход | Успешный ответ |
| --- | --- | --- |
| `GET /` | — | HTML-студия, `200` |
| `POST /symbol-art` | HTML-форма `text`, `banner` | HTML с результатом, `200`; при `Accept: application/json` — `{result,text,banner}` |
| `POST /api/suggest` | `{"text":"Happy Birth"}`; минимум 3 символа без краевых пробелов | `{"suggestions":[...]}`; 3–5 строк короче 50 символов |
| `POST /api/recommend-banner` | `{"text":"WELCOME"}` | `{recommended,reasoning,alternatives}` |
| `POST /api/variations` | `{"text":"hello"}` | `{"variations":[...]}`; 3–5 объектов `text`, `description`, `suggested_banner` |

Примеры для **каждого** маршрута:

```sh
curl -i http://localhost:8080/

curl -i http://localhost:8080/symbol-art \
  --data-urlencode 'text=Hello' --data-urlencode 'banner=standard'

curl -s http://localhost:8080/symbol-art \
  -H 'Accept: application/json' \
  --data-urlencode 'text={123}\n<Hello> (World)!' --data-urlencode 'banner=standard'

curl -s http://localhost:8080/api/suggest \
  -H 'Content-Type: application/json' -d '{"text":"Happy Birth"}'

curl -s http://localhost:8080/api/recommend-banner \
  -H 'Content-Type: application/json' -d '{"text":"WELCOME"}'

curl -s http://localhost:8080/api/variations \
  -H 'Content-Type: application/json' -d '{"text":"hello"}'
```

`400` означает ошибку ввода; `404` — неизвестный маршрут, отсутствующий баннер или HTML-шаблон; `405` — неподдерживаемый метод с заголовком `Allow`; `500` — ошибка генерации/шаблона или некорректный ответ модели; `503` — недоступный LLM, неверная live-конфигурация, сетевой сбой или таймаут. Ошибки API всегда возвращаются как JSON. Статические каталоги не выдают списки файлов.

### Фронтенд

`index.html` содержит форму и подключает `result.html` как частичный шаблон. `error.html` — отдельная страница восстановления. Общая логика студии находится в `app.js`; подсказки, рекомендации и идеи — в отдельных файлах, как требует ТЗ.

JavaScript постепенно расширяет HTML-форму: отправляет её асинхронно, обновляет результат, отменяет устаревшие запросы и показывает состояния загрузки и ошибки. Сохранённая история находится только в `localStorage` данного браузера. Удаление данных сайта удалит историю; блокировка хранилища не мешает генерации. Копирование зависит от разрешений браузера, скачивание `.txt` остаётся доступным.

## AI Features / AI-функции

### Подсказки и mock-режим

`LLM_BASE_URL` отсутствует или пуст → `MockMode()` возвращает `true`; сетевых вызовов нет. Известные начала фраз получают готовые завершения, остальные — воспроизводимые варианты. Например, `Happy Birth` возвращает:

```json
{"suggestions":["Happy Birthday!","Happy Birthday [Name]","Happy Birthday Team!"]}
```

В live-режиме `Suggestions` строит запрос к модели, проверяет ответ и возвращает 3–5 непустых, разных ASCII-строк короче 50 символов. Успешные live-подсказки кэшируются на 5 минут, максимум 128 наборов. Ошибки не кэшируются.

### Рекомендации без LLM

Правила применяются в следующем порядке:

1. Если не менее трети символов — знаки/украшения, выбирается `thinkertoy`.
2. Если все буквы заглавные или текст не длиннее 6 символов — `shadow`.
3. Если длина больше 12 — `standard`.
4. Иначе — `thinkertoy`.

Пробелы по краям убираются, переводы строк не считаются декоративными знаками. Ответ содержит объяснение и две альтернативы с оценкой от 0 до 1. `WELCOME` → `shadow`, `Hello world from Astana` → `standard`, `Hi there` → `thinkertoy`. Этот endpoint не зависит от состояния LLM.

### Творческие варианты

`/api/variations` делает отдельный LLM-вызов и проверяет 3–5 разных вариантов, описания короче 30 символов и разрешённые имена баннеров. В mock-режиме выдаёт четыре варианта: деловой, выразительный, дружелюбный и декоративный. Выбор варианта заполняет текст и переключает баннер.

### Live-протокол и восстановление

- URL без специального окончания: добавляется `/api/generate`, используется Ollama API с `stream:false`.
- URL, оканчивающийся `/v1`: добавляется `/chat/completions`.
- Полные пути `/api/generate` и `/chat/completions` также поддерживаются.
- Разрешены только HTTP(S), без логина/пароля, query-параметров и фрагмента в URL. Bearer-ключ передаётся заголовком. HTTP-перенаправления отключены.
- Весь вызов, включая максимум один повтор и чтение ответа, ограничен **10 секундами**. Повтор выполняется при сетевом сбое и HTTP `429/500/502/503/504`, с задержкой 100 мс.
- Размер ответа ограничен 1 MiB, JSON и содержимое проверяются до отправки клиенту.
- Live-сбой возвращает ошибку; приложение не подменяет её незаметно mock-ответом. Генератор и рекомендации продолжают работать.

## Проверка и аудит

```sh
go test -race -count=1 -cover ./...
go vet ./...
go build -o bin/symbol-web ./cmd/server
```

В GitHub Actions те же проверки выполняются для push и pull request, вместе с проверками `gofmt`, синтаксиса JavaScript и 34 тестами асинхронного поведения фронтенда. Для локальной проверки JavaScript нужен Node.js 18+: `node --check static/js/app.js` (повторите для остальных `.js`) и `node --test tests/frontend.test.js`. Тесты используют только стандартные модули Node.js и имитацию DOM: они проверяют debounce, отмену, устаревшие ответы и безопасный вывод; визуальную проверку браузером они не заменяют.

Полный список требований и сценарии интерфейса — в [AUDIT.md](AUDIT.md). Отдельно доступны [итоговый отчёт по 44 пунктам](docs/AUDIT_REPORT_RU.md), [ответы на 49 вопросов аудитора](docs/AUDITOR_ANSWERS_RU.md) и [проверка отказоустойчивости](docs/RESILIENCE_REPORT_RU.md). Автотесты сравнивают оба примера аудит-листа с эталонами (без незначащих конечных пробелов и внешних пустых строк), проверяют три шрифта, ошибки HTTP/шаблонов, LLM-протоколы, отмену/таймауты, повторные запросы, кэш и параллельные обращения. Live-протокол проверяется локальными HTTP-серверами в тестах: это не утверждение, что внешняя модель установлена или доступна на вашей машине.
