# Отдельная проверка отказоустойчивости

Дата: 25 сентября 2026 года. Объект — локальный Symbol-Web, исходная версия `33e371c`, затем исправленная версия `73d0bb0`. Испытания ограничены локальными HTTP-серверами и временными копиями файлов. Боевые файлы баннеров/шаблонов не удалялись, чужие сервисы нагрузке не подвергались, ключи не использовались.

## Нагрузочные и конкурентные проверки

- **1000 реальных HTTP-запросов, 32 параллельных клиента, 0 ошибок.** Смесь: максимальный текст 1000 символов в shadow, подсказки, рекомендации, вариации, намеренно неверный JSON тип. Для неверного ввода ожидается 400 — это успешная обработка сценария, не сбой.
- Измеренная длительность отдельного локального прогона без race: **71 мс**. Это наблюдение на данной машине, не обещание пропускной способности для другой среды или реальной модели.
- Полный Go-прогон с `-race` проходит: генератор не содержит общего изменяемого состояния, кэш защищён mutex и копирует срезы.
- AI-проверки включают **640 конкурентных операций** чтения/изменения возвращённых значений; отдельный существующий тест проверяет **1600 конкурентных записей** в кэш.
- После нагрузки и после 40 обрывов незавершённых клиентских запросов главная продолжает отвечать 200.

## Настоящий процесс сервера

В тестах запускается отдельный дочерний процесс с копиями шрифтов и шаблонов во временном каталоге, пустым API-ключом и локальным адресом. Проверяется реальный `run`, обработка сигналов и настройки `http.Server`. Ненулевой код завершения дочернего процесса, включая срабатывание race detector, приводит к провалу родительского теста с диагностикой.

| Сценарий | Наблюдение |
| --- | --- |
| Удалён уже использованный banner/index/result | 404 |
| Повреждён banner или синтаксис шаблона | 500 |
| Файл восстановлен без перезапуска | 200 |
| Сам error-шаблон отсутствует | Текстовый fallback с исходным статусом, остальные страницы работают |
| Заголовок больше допустимого размера | 431 |
| Клиент не заканчивает заголовки | Соединение освобождается через **5,001 с** |
| Клиент не заканчивает тело запроса | Соединение освобождается через **15,002 с** |
| Другой клиент приходит во время медленного запроса | Получает 200 |
| SIGTERM при активном LLM-запросе | Новые соединения прекращаются; активный запрос получает корректный 200, процесс завершается с кодом 0 |
| Паника до записи ответа | 500, JSON для API |
| Паника после записи части JSON | Незавершённый ответ/соединение прерывается; клиент не получает успешно завершённый повреждённый JSON |

Значения 5/15 секунд измерены с небольшим допустимым запасом в тесте. На уровне HTTP-протокола ошибка медленного клиента может проявиться закрытием соединения, а не JSON — запись ответа уже может быть невозможна.

## Отказы LLM и восстановление

Проверены оба протокола: Ollama и OpenAI-compatible. Локальный HTTP-backend имитирует правильные данные, ошибочные структуры, обрыв TCP до ответа, обрыв в середине тела, несовпадающий Content-Length и зависшее тело после заголовков.

- Общий deadline LLM — 10 секунд, включая повтор и чтение тела. Отдельный интеграционный тест действительно ждёт этот срок и проверяет 503 и дальнейшую работоспособность сервера.
- Более короткий caller deadline и отмена клиента не игнорируются; отмена во время задержки между попытками прекращает повтор.
- Матрица из 11 статусов проверяет, какие ошибки повторяются и как классифицируются. Повтор максимум один для сети и 429/500/502/503/504.
- Пустой, повреждённый, слишком большой или непригодный ответ модели не попадает во фронтенд; формат/кодировка и количество элементов проверяются.
- Redirect отключён. URL и ключ не раскрываются в сообщении транспортной ошибки.
- Успешные подсказки кэшируются; ошибки — нет. Истечение и вытеснение проверены.

## Fuzz-тесты вне аудит-листа

Каждая цель запускалась с бюджетом 10 секунд и двумя worker-процессами. Небольшое превышение времени включает завершение текущих испытаний. Указаны фактически выполненные исполнения; они не означают столько же уникальных найденных сценариев.

| Цель | Исполнений | Время завершения | Итог |
| --- | ---: | ---: | --- |
| `FuzzMockResponseContracts` | 362 558 | 10,506 с | PASS |
| `FuzzParseVariations` | 384 581 | 11,468 с | PASS |
| `FuzzParseSuggestions` после исправления | 386 844 | 10,450 с | PASS |
| `FuzzGenerate` | 597 992 | 11,695 с | PASS |
| `FuzzJSONEndpoints` | 318 684 | 10,730 с | PASS |
| `FuzzFormRequests` | 316 607 | 11,461 с | PASS |
| **Итого** | **2 367 266** | — | **Провалов нет** |

Проверяются отсутствие panic, валидные статусы/JSON, детерминизм, допустимые символы/длины/баннеры, уникальность mock и отсутствие частичного результата при ошибке. Поля/ввод ограничены в самих fuzz-целях, чтобы испытание оставалось конечным по ресурсам.

Воспроизведение:

```sh
go test ./internal/ai -run '^$' -fuzz '^FuzzMockResponseContracts$' -fuzztime=10s -parallel=2
go test ./internal/ai -run '^$' -fuzz '^FuzzParseSuggestions$' -fuzztime=10s -parallel=2
go test ./internal/ai -run '^$' -fuzz '^FuzzParseVariations$' -fuzztime=10s -parallel=2
go test ./internal/ascii -run '^$' -fuzz '^FuzzGenerate$' -fuzztime=10s -parallel=2
go test ./internal/handlers -run '^$' -fuzz '^FuzzJSONEndpoints$' -fuzztime=10s -parallel=2
go test ./internal/handlers -run '^$' -fuzz '^FuzzFormRequests$' -fuzztime=10s -parallel=2

go test ./internal/handlers -run TestConcurrentHTTPStress -count=1 -v
go test ./cmd/server -run '^TestProcess' -count=1 -v
go test -race -count=1 ./...
node --test tests/frontend.test.js
```

Обычный CI запускает начальные corpus-примеры всех fuzz-функций как тесты. Непрерывная генерация случайных входов запускается приведёнными командами отдельно.

## Фронтенд: 34 программных теста

Исполняются настоящие JS-файлы в `node:vm` с контролируемыми DOM, таймерами и сетью. Покрыты 300 мс debounce, устаревшие успехи/ошибки, немедленная отмена, минимальный ввод, безопасный HTML-подобный текст, клавиатурная навигация, закрытие диалога и retry.

Новые сценарии исполнения `app.js`: таймаут fetch и зависшего JSON-тела 12 секунд, разрыв сети, не-JSON ответ, HTTP-ошибка, отмена и очистка таймера, редактирование во время генерации, допустимые пробелы, испорченный/слишком большой/заблокированный localStorage, лимит и восстановление истории, clipboard success/fallback, точный текст Blob/имя `.txt` и освобождение ресурсов при ошибке скачивания.

## Границы результата

Это учебный HTTP-сервис, прошедший указанный набор проверок. Бесконечная нагрузка, DDoS, исчерпание диска/памяти ОС и отказ аппаратуры здесь не моделировались. Нет rate limiting, очереди запросов к LLM, singleflight или circuit breaker; одновременные cache miss могут независимо вызвать backend. Для публичной эксплуатации лимиты нагрузки задаются отдельно на уровне приложения или reverse proxy.

Визуальная/межбраузерная приёмка и реальная внешняя модель не подтверждены этим прогоном. Это отмечено в [полном отчёте по аудит-листу](AUDIT_REPORT_RU.md); конечные fuzz-прогоны и процент покрытия не являются гарантией отсутствия всех возможных дефектов.
